SIGN-BRIDGE

A Dual-Communication Robotic Translator

Built for Indian Sign Language (ISL) · Scrap-Material Robotic Hands + AI Vision



Project Implementation Plan

Sequence · Architecture · Bill of Materials · Schedule · Risk Plan



1. Project Objective

Sign-Bridge is a two-way (dual) communication system that breaks down the barrier between Deaf/Hard-of-Hearing signers and hearing individuals in India, using Indian Sign Language (ISL) as the medium. It combines a scrap-material robotic hand pair, a webcam-based AI vision pipeline, and a microcontroller-driven servo system to translate:

ISL signs → spoken/written language, for a hearing person to understand a Deaf signer.

Spoken/written language → ISL fingerspelling and gestures, physically performed by the robotic hands, for a Deaf person to understand a hearing speaker.



Why ISL specifically changes the design: Unlike the American Sign Language (ASL) alphabet, which is almost entirely one-handed, the ISL alphabet is predominantly two-handed — most letters and numbers require both hands to shape a single sign. This means Sign-Bridge cannot be reduced to a “one hand fingerspells everything” design the way an ASL project could. A two-hand robotic system is a functional requirement for ISL fingerspelling, not just an upgrade for whole-word vocabulary.

2. System Architecture: The Dual Communication Loop

2.1 Path 1 — Human Signs → Text/Speech (Input Path)

Deaf user signs in ISL in front of a laptop webcam → MediaPipe/OpenCV vision pipeline extracts hand landmarks → a trained classifier maps the landmark pattern to an ISL letter/word → result is rendered as on-screen text and/or spoken aloud via text-to-speech for the hearing user.

2.2 Path 2 — Text/Speech → Robotic Hands (Output Path)

Hearing user types or speaks into a microphone → speech-to-text (if spoken) converts audio to a string → the controller breaks the string into letters/known-words → a pre-calibrated servo-angle sequence is looked up for each letter/word → Arduino drives the two scrap-material robotic hands to physically form the corresponding ISL signs in sequence.

2.3 Data Flow Summary

[Deaf User] ──(Signs)──> [Webcam + MediaPipe]

──> [Text / Speech Output] ──> [Hearing User]

[Deaf User] <──(Watches Hands)── [Robot Hands]

<── [Servo Sequencer] <── [Text / Speech Input] <── [Hearing User]



3. Recommended Project Sequence

Build in this order. Each phase produces a working, demoable milestone before moving to the next — this avoids the common failure mode of wiring everything at once and debugging blind.

Phase 0 — Research & ISL Reference Collection

Phase 1 — Mechanical Design: build ONE scrap-material hand

Phase 2 — Electronics & Wiring: 5 servos → Arduino Uno (single hand)

Phase 3 — Output Programming: Text/Speech → single-hand ISL fingerspelling

Phase 4 — Input Pipeline: Webcam + MediaPipe → ISL sign → Text/Speech

Phase 5 — Scale to Second Hand: 10 servos → Arduino Mega, full two-hand ISL letters

Phase 6 — Whole-Word / Phrase Vocabulary Layer

Phase 7 — Integration Testing, Calibration & Troubleshooting

Phase 8 — Final Demo Packaging



4. Detailed Implementation Plan

Phase 0 — Research & ISL Reference Collection

Collect a reference chart of the ISL manual alphabet (A–Z) and 0–9, noting which letters are one-handed vs two-handed.

Identify 5–10 common ISL whole-word signs to target first (e.g. “hello”, “thank you”, “yes”, “no”, “help”, “water”, “food”, “family”).

Source or plan to record a small ISL image/video dataset for training the vision classifier, since most public hand-gesture datasets (e.g. Kaggle ASL sets) are ASL-based and will not transfer directly to ISL two-handed signs.

List locally available scrap: cereal-box cardboard, PVC/plastic bottles, drinking straws, fishing line/dental floss, an old glove.

Phase 1 — Mechanical Design (Build One Hand First)

Trace and cut a hand-and-forearm shape from stiff cardboard or a flattened plastic bottle.

Cut drinking straws into knuckle-length segments and glue/tape them along each finger as joint sleeves.

Thread strong string (fishing line or dental floss) through each straw ‘finger’, anchoring one end at the fingertip.

Build a simple palm-back mounting plate to hold 5 servo motors, with a return spring or elastic band per finger so it relaxes when the servo releases tension.

Reinforce high-stress points (finger base, palm-servo mounts) with extra cardboard layers or hot glue to fight the friction/tearing weak point called out for scrap builds.

Phase 2 — Electronics & Wiring (Single Hand)

Mount 5x SG90 micro servos in the forearm/palm housing, one per finger tendon.

Wire servo signal pins to 5 PWM-capable pins on an Arduino Uno; wire all servo grounds to a common ground with the Arduino.

Power the servos from a separate 5V supply (not the Arduino 5V pin) to avoid brownouts, sharing only ground with the Arduino.

Add a breadboard/terminal block junction so wiring can be re-checked without resoldering.

Phase 3 — Output Programming (Text/Speech → Single-Hand Signs)

Write an Arduino sketch that maps a servo-angle set to each one-handed ISL letter/number the single hand can perform.

Build a simple serial-controlled interface: a companion Python script on the laptop accepts typed text (or speech-to-text output) and sends the matching letter sequence to the Arduino over USB serial.

Calibrate each servo angle manually against the physical hand, since flexible scrap joints need fine-tuning beyond theoretical angles.

Phase 4 — Input Pipeline (Webcam → ISL → Text/Speech)

Use a laptop webcam with Google MediaPipe Hands to extract real-time hand-landmark coordinates — this avoids building a costlier sensor glove.

Train or fine-tune a lightweight classifier (e.g. a small scikit-learn/TensorFlow model) on the recorded ISL landmark dataset from Phase 0 to recognize target letters/words.

Display the recognized sign as on-screen text and pass it to a text-to-speech engine (e.g. pyttsx3 or a cloud TTS API) so a hearing user gets spoken output.

Phase 5 — Scale to Two Hands (Full ISL Alphabet Capability)

Duplicate the Phase 1 mechanical build for a second hand (mirror-image), since most ISL letters require both hands together.

Migrate the controller from Arduino Uno to Arduino Mega to get the 10+ PWM pins needed for 10 finger servos.

Extend the servo-angle lookup table so each ISL letter/number is defined as a synchronized pose across both hands, not just one.

Add a simple wrist/arm-position stage (servo or fixed bracket) if a sign requires the two hands to be positioned relative to each other, not just finger shapes.

Phase 6 — Whole-Word / Phrase Vocabulary Layer

Layer a small “word library” on top of fingerspelling: map common whole-word ISL signs (from Phase 0's shortlist) to their own two-hand motion sequences, since real ISL communication relies heavily on these rather than spelling everything out.

Update the text-to-sign controller so it checks the incoming text against the word library first, and falls back to letter-by-letter fingerspelling for anything not in the library.

Phase 7 — Integration Testing, Calibration & Troubleshooting

Run end-to-end tests of both communication paths together with real signers/speakers if possible.

Expect and budget time for: snapped tendon strings, cardboard joints loosening under repeated pulls, and servo-angle drift needing re-calibration.

Log misrecognitions from the vision model and add extra training samples for the letters/words it confuses most.

Phase 8 — Final Demo Packaging

Add a simple enclosure/labeling so the two hands, camera, and controller box present cleanly for a demo or evaluation.

Prepare a short live-demo script: one sentence signed by a human → spoken by the system, and one spoken sentence → signed by the robot hands.

8. Key Risks & Mitigation

Risk

Mitigation

Cardboard tears or bends under servo pulling force

Double-layer stress points; reinforce palm mounts; use PVC/bottle plastic for high-load joints instead of pure cardboard

Tendon strings snap or slip

Use non-stretch fishing line/dental floss; knot with a bead or washer stop at the fingertip anchor

Servos lack fine control for precise ISL hand shapes

Manually calibrate angle-per-letter tables per physical hand rather than using theoretical angles; add mechanical stops

ISL vision dataset is scarce compared to ASL datasets

Record a small custom dataset of the target letters/words in Phase 0 rather than relying on ASL-labeled public datasets

Two-handed ISL signs need hand-to-hand coordination, not just finger shapes

Add a fixed or servo-driven relative positioning stage between the two hand mounts in Phase 5

Arduino Uno pin limit blocks 10-servo control

Move to Arduino Mega before wiring the second hand, as planned in Phase 5

9. Future Scope

Expand the ISL word library from 5–10 signs toward a broader practical vocabulary.

Replace the scrap glove/webcam setup with a lightweight flex-sensor glove for more consistent input recognition.

Add facial-expression or head-movement capture, since ISL (like most sign languages) uses non-manual markers alongside hand shapes.

Package the whole system into a portable kiosk form factor for use at reception desks, hospitals, or government service counters.
